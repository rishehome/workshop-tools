# Workshop renders and overviews

Workshop overviews use the same cream, forest green, Manrope typography and
main 3:2 card and 9:16 Story layout as the products repository. The template and CAD
helpers are vendored here so this repository works without a sibling checkout.
The renderer creates five studio views in a solid Nardo-inspired gray
(`#9C9D9F`, roughness 0.52), with no wood textures. This color is an illustrative
finish, not a material specification or an exact automotive paint match.
Renders are RGBA PNGs with transparent backgrounds and smooth alpha edges;
studio lighting remains on the object. Overview cards retain their own layout
backgrounds.

## Setup

Use Python 3.10+, FreeCAD with its Python runtime, and Blender. This pipeline
was verified with Blender 3.4.1. From this repository:

```sh
python3 -m venv venv
venv/bin/python -m pip install -r tools/product_overview_requirements.txt
venv/bin/python -m playwright install chromium
```

On macOS the scripts detect FreeCAD in `/Applications/FreeCAD.app`; elsewhere
set `FREECAD_PYTHON` to a Python executable with FreeCAD, Part and MeshPart.
Use `/Applications/Blender.app/Contents/MacOS/Blender` if `blender` is not on PATH.

## Generate

```sh
python3 tools/render_tools.py --dry-run
blender --background --python-exit-code 1 --python tools/render_tools.py --
venv/bin/python tools/build_product_overview.py . --batch --generate-info --scale 1
```

Run the commands sequentially, finishing renders before overviews. To update
one design or choose another plain color:

```sh
blender --background --python-exit-code 1 --python tools/render_tools.py -- --path bit-holder/generic --color 8B9298
venv/bin/python tools/build_product_overview.py bit-holder/generic --batch --generate-info --scale 1
```

`--path` accepts repository-relative design directories, variant directories or
source files. Renders are replaced on each run. `--device cpu` disables automatic
Metal acceleration. Color accepts six hexadecimal digits with an optional `#`.
When changing color, update any color-specific caption in `overview.json` too.

Each design's published `exports/<variant>/` must contain exactly one STEP/STP
file. That export is authoritative even when the editable CAD has newer changes.
Designs without exports use saved solid bodies in `object.FCStd`, excluding CAM
geometry, and write into `main/object/`. Backups are never selected. The scripts
do not recompute, modify, or save source CAD. Invalid saved geometry is reported;
its faces can render, but invalid solids cannot provide measured dimensions.

## Files and layout

Each variant (or `main/object/`) contains:

- `renders/solid-{front,side,top,back,three-quarter}.png`: 1200 × 900 transparent studio views.
- `renders/sources.json`: source hash, color, transparency, renderer version and CAD validity.
- `overview.json`: editable title, copy, image choices and detail crop.
- `model-facts.json`: measured CAD dimensions and source hash.
- `overview/product-overview.png` and `overview/sources.json`: main 3:2 card.
- `overview/story/product-overview.png` and `overview/story/sources.json`: 9:16 Story card.

Both layouts are generated by default: main landscape (1536 × 1024) and
Instagram Story (1080 × 1920) at `--scale 1`. Use `--format landscape` or
`--format story` for one layout, or `--format all` for both. The default scale is
2 for higher-resolution output. No other aspect ratios are generated.

Dimensions default to **X = width, Y = height, Z = depth**, in millimetres,
matching the renderer's XY front view. These are axis-aligned saved CAD extents,
not measured finished-tool dimensions. Use `--axes xzy` or another permutation
with `--generate-info` when a model needs a different mapping. Saved mapping and
units persist on subsequent refreshes. Do not infer size from variant names.

Edit `overview.json` to customize `name`, `category`, `caption`, `feature_title`,
`feature_text`, `feature_note`, `alternate_title`, `collection`, `images` and
`detail_crop` (`scale`, `x`, `y`). The default image slots are three-quarter,
front detail, and front. Matching image stems in `photos/` take precedence over
renders. Set `dimensions: null` to suppress dimensions, or supply a verified
width/height/depth/unit object. Long copy that overflows a card fails rendering.
Use `--help` on either generator for the complete options.

After editing source geometry, regenerate renders and run the overview command
with `--generate-info`. Stale dimension hashes are rejected. Rendering previews
does not mark a tool as finalized or ready for fabrication.

## Face directions

All source formats default to **top = +Z**, **front = -Y**, and **right = +X**.
The named axis is the outward direction of that face in source coordinates.
Positive Z therefore appears upright. OBJ imports preserve source axes too.

Save settings beside the exact source, appending `.render.json` to its full
filename (for example `object.FCStd.render.json` or `assembly.step.render.json`):

```json
{
  "top": "+Z",
  "front": "-Y"
}
```

`top` and `front` accept `+X`, `-X`, `+Y`, `-Y`, `+Z`, or `-Z` and must be
perpendicular. Omitted fields use the defaults. These two faces determine the
other four: bottom and back are opposite, and right is top crossed with front.
The side image shows the right face; the top image has the back toward its upper edge.

Override saved settings for every selected model with `--top-axis=+Z
--front-axis=-Y` after Blender's `--` separator. Use the equals form for negative
axes. For a model whose broad front points along +Z and whose top points along
+Y, use `--top-axis=+Y --front-axis=+Z`. Invalid settings also fail in `--dry-run`.

These settings change camera directions only, leaving CAD geometry, measured
dimensions and GLB placement unchanged. Existing images need regeneration;
then rebuild any overview cards that use them.

### Orientation in model facts

You can also add an `orientation` field to the model's `model-facts.json`
(next to its `renders/` directory):

```json
"orientation": {"top": "+Z", "front": "-Y"}
```

Products store model facts inside `export.json`, under `models["."]` for an
export root or `models["parts/<part>"]` for a part. Add the same `orientation`
field to that model entry. A standalone `model-facts.json` is also read when
there is no native model-facts entry.

Precedence, per face: command-line override, source `.render.json`, model facts,
then defaults. Regenerating measurements preserves authored orientation.
The existing `axes` field controls dimension labels, independently of camera orientation.
